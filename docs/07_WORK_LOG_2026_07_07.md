# Work Log 2026-07-07

## Nội dung chính

Hôm nay xử lý lại hướng thiết kế luồng khởi tạo hồ sơ vay: chuyển nghiệp vụ lưu nháp nhiều bước từ bảng `loan_application_draft` sang dùng trực tiếp `loan_application` làm nguồn dữ liệu chuẩn ngay từ đầu.

Lý do thay đổi:

- State diagram hiện tại mô tả trạng thái của `Loan Application`, không phải trạng thái của một bảng draft tách riêng.
- Nếu hoàn thiện draft xong mới tạo `loan_application`, hồ sơ vay thật không thể phản ánh đúng các trạng thái `APP_CREATED`, `APP_IN_PROGRESS`, `APP_COMPLETED`.
- Frontend đang dùng API draft, nên backend vẫn giữ path cũ để giảm lỗi tích hợp, nhưng mapping nội bộ chuyển sang `loan_application`.

## Code đã thực hiện

### 1. Migration database V11

`backend/loan-onboarding/src/main/resources/db/migration/V11__move_draft_flow_to_loan_application.sql`

Đã thêm:

- State mới/cập nhật state: `APP_CREATED`, `APP_IN_PROGRESS`, `APP_COMPLETED`, `APP_SUBMITTED`, `APP_CANCELLED`, `APP_EXPIRED`.
- Transition mới theo flow onboarding: `IDENTIFY_COMPLETE`, `COMPLETE_APPLICATION`, `SUBMIT`, `CANCEL`, `EXPIRE`, `REOPEN`.

- Bảng `loan_application_step_data` để lưu payload JSON từng bước theo hồ sơ vay.
- Bảng `loan_application_step_history` để audit thao tác từng bước.
- Script map hồ sơ cũ còn ở `APP_DRAFT` sang `APP_CREATED`.

### 2. Entity và repository

Đã thêm/cập nhật:

- `LoanApplication`: thêm `currentStep`, `expiredAt`, `createdAt`, `updatedAt`; bổ sung `@PrePersist` và `@PreUpdate` để tự set thời gian.
- `LoanApplicationStepData`: entity cho bảng `loan_application_step_data`.
- `LoanApplicationStepHistory`: entity cho bảng `loan_application_step_history`.
- `LoanApplicationStepDataRepository`: truy vấn step payload theo `applicationCode` và `stepCode`.
- `LoanApplicationStepHistoryRepository`: lưu lịch sử thao tác step.
- Enum `LoanApplicationStepStatus`: chuẩn hóa status step `NOT_STARTED`, `IN_PROGRESS`, `COMPLETED`.
- Enum `LoanApplicationStepHistoryAction`: chuẩn hóa action audit step.
- Enum `LoanApplicationState`: bổ sung state onboarding mới.

### 3. Service xử lý onboarding

File:

`backend/loan-onboarding/src/main/java/com/f88/loanonboarding/service/impl/LoanApplicationDraftFlowServiceImpl.java`

Đã refactor logic:

- `createDraft`: tạo `loan_application` ngay từ đầu; `draftCode` trả về bằng `applicationCode` để tương thích FE cũ.
- `getDraft`: load dữ liệu từ `loan_application` và `loan_application_step_data`.
- `findDrafts`: lấy danh sách từ `loan_application`, mapping status cũ sang state mới.
- `completeStep`: lưu payload step, set step `COMPLETED`, cập nhật current step, chuyển state khi đủ điều kiện.
- `submit`: chỉ cho nộp khi hồ sơ ở `APP_COMPLETED`, tất cả step hoàn thành và không còn step cần review.
- `cancel`: chuyển hồ sơ sang `APP_CANCELLED`.

Logic chuyển trạng thái chính:

- Tạo hồ sơ chưa có payload định danh: `APP_CREATED`.
- Tạo hồ sơ có payload định danh: `APP_IN_PROGRESS`.
- Hoàn thành bước `CUSTOMER_IDENTIFY` từ `APP_CREATED`: chuyển `APP_IN_PROGRESS`.
- Hoàn thành tất cả step: chuyển `APP_COMPLETED`.
- Submit hồ sơ: chuyển `APP_SUBMITTED`.

### 4. Controller API

File:

`backend/loan-onboarding/src/main/java/com/f88/loanonboarding/controller/LoanApplicationDraftController.java`

Đã cập nhật:

- Giữ path `/api/v1/loan-application-drafts` để frontend hiện tại ít phải sửa.
- Cập nhật mô tả OpenAPI để làm rõ backend tạo `loan_application` ngay từ đầu.
- Bỏ endpoint autosave `PUT /{draftCode}/steps/{stepCode}` khỏi controller vì hiện tại không dùng auto save.
- API `complete` là API chính để lưu và hoàn thành từng bước.
- API `submit` không còn tạo hồ sơ vay mới; chỉ chuyển `loan_application` hiện có sang `APP_SUBMITTED`.
